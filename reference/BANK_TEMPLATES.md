# Bank template implementation and validation

Use this workflow for bank salary-upload formats in Nabd Pay. The source of truth is the current clone's `docs/pay/features/bank-file.md`, service contract, interpreter, and tests.

## Current product contract

- Studio route: `/config/bank-templates`; generation route: `/bank-file`.
- Templates are data-driven `BankFileTemplates` rows carrying a JSON `spec`.
- Supported layouts: `delimited`, `fixed_width`, `xlsx`, and `xml`.
- Records may contain headers, body rows, and trailers using the interpreter's constrained source catalogue. Do not invent a source key.
- XLSX supports per-field `cellType` (`auto`, `text`, `number`, `date`) and optional `numFmt`.
- Filename tokens include cycle/calendar/value-date/current-date and month-period variants supported by the current interpreter.
- Credit generation uses eligible actual payroll results, the supported bank-transfer method, primary bank data, positive net pay, and one currency. The current code—not an old sample—defines the exact gates.
- Preview data is masked/synthetic. Full account and identifier values belong only in encrypted Core storage and generated bytes.
- Regeneration validates and renders the replacement before removing the prior export.

## Live payroll eligibility and EC prerequisites

The template is the final renderer, not the source of employee payment data. A payroll result becomes a bank-file row only when all of these conditions are true in the current application:

1. The employee has an actual result in the selected cycle.
2. `Employments.paymentMethod` is exactly the supported bank-transfer code `05`.
3. A non-deleted `PersonBankAccounts` row exists for the employment. The lowest numeric `priority` wins.
4. The selected account has an `accountNumber` or `iban` in Core.
5. Net pay is positive and the file has one consistent currency.

Core obtains the data from SuccessFactors CompoundEmployee:

- Legacy tenants: `payment_information` with `account_number`, `deposit_type`, `pay_priority`, and the optional bank/routing/IBAN fields.
- MDF tenants: `PaymentInformationV3` / `PaymentInformationDetailV3*`. Supply `accountNumber`, `paymentMethod`, `payType=MAIN` for the primary payment, and `paymentMethodOrder` where multiple methods exist.
- The current transformer discards a payment row without `accountNumber`, even when an IBAN is present. EC must therefore provide the account number until the transformer is changed.
- Turn on Track Changes for `PaymentInformationV3` so delta replication can detect later banking updates.
- QNB additionally needs a usable branch/routing value. The other three current drafts consume the account number but not IBAN.

After onboarding or changing the mapping, use Core > Employees > Actions > Re-initialize from scratch. A delta sync does not revisit unchanged employee records.

## Current product limitations relevant to bank templates

- The Studio exposes decimals, date format, cell typing, Excel number format, fixed width, and alignment, but it does not expose all interpreter features. Hidden-only features include amount minor-unit scaling, thousands/sign rules, string trim/case, numeric add, per-field pad/truncate, CSV quote policy/quote character, and UTF-8 BOM.
- Studio supports only six date formats and has no `DDMMYY` option. CIB's two six-digit dates therefore require an operator-supplied parameter in the current draft.
- Operator parameters have key, label, and default only. There is no required flag, regex, length, checksum, or bank-specific validation.
- XLSX generation writes values and number formats but does not model an uploaded workbook's arbitrary styles or legacy `.xls` output.
- The Bank File page exposes download and regeneration but not the existing `recallBankFile` service action. An invalid occupying export cannot be recalled through the current Pay UI.
- The Bank File validation label “All employees have a bank account” is narrower than it sounds: employees rejected first as non-bank-payment are not counted as missing-account failures. Keep the Payroll readiness check `bank_accounts_present` active as a blocker.
- `syncPaymentInfoV3` exists in the Core service configuration but is not exposed on the current Advanced settings page. A tenant using MDF Payment Information needs this configured during onboarding or the UI needs to add the control.

## From a bank sample to a Nabd template

1. Preserve the source file and compute its hash.
2. Identify its real type by content, not extension. For spreadsheets record workbook/sheet names, used range, typed cells, number formats, merged cells, hidden rows/columns, formulas, and sample values.
3. Derive the record grammar: encoding, delimiter/quote/newline or fixed widths; header/body/trailer; field order; constants; padding/alignment; decimal/date rules; filename rule.
4. Classify every field as employee source, file metadata, operator parameter, aggregate, literal, or `Unknown`.
5. Map only to sources accepted by the current `spec-interpreter.js`. Resolve every `Unknown` with an approved bank specification or stakeholder; never guess.
6. Create a uniquely keyed inactive draft through Bank Template Studio, then use validation/preview.
7. Compare generated structure with the source at byte/cell level. For XLSX verify cell types and formats, not only displayed text.
8. Test empty/invalid required values, unicode/encoding, length limits, totals, record count, dates, decimals, account leading zeroes, filename tokens, and masking.
9. Generate against synthetic eligible payroll data, download, reopen, and reconcile header/trailer totals and every employee row.
10. Activate only after evidence is recorded. Keep the original, mapping worksheet, template JSON export, generated artifact, validation results, and cleanup/rollback key.
11. Before real-cycle validation, enable the Pay blockers `bank_accounts_present` and `has_payable`. Confirm the preview has at least one included row before generating.
12. Reconcile the downloaded file to the Bank File preview: employee count, total amount, currency, value date, filename, header/trailer totals, field widths or worksheet cell types, and every required operator parameter.

## Four-file project gate

For the workspace samples (`D2K_CIB.txt`, `D2K_Credit_Agricole.xlsx`, `D2K_HSBC_10_2025.csv`, `D2K_QNB_10_2025.xls`), complete local parsing and template validation first. Configure the deployed QA tenant only after all four pass locally. One bank passing does not authorize activation of the others.
